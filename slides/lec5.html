Prompt engineering

Definition – what is prompt engineering

Prompt engineering is the practice of carefully designing, crafting, and refining the input text (prompts) given to generative AI models to elicit the most accurate, relevant, and desired output.

Prompt vs. Traditional Software engineering

Prompt engineering is based on natural language

Software engineering is primarily based on programming

An Iterative process

Prompt engineering is fundamentally an iterative process of experimentation and refinement

A single, one-shot prompt rarely yields an optimal result

This empirical process is what truly separates prompt engineering from a simple, one-time query

Think in the same terms as when you write code

  • Write, compile, test, refactor
  • Prompt engineering: initial prompt, review model’s response, adjust the prompt

A structure for AI Agent prompts

Roles

Tasks

Requirements

Instructions

Role

Defines the persona the model should adopt. Influences tone, knowledge, and style.

“Act as a senior software architect.”

Task

The specific, clear objective for the model.

“Outline a project plan for a new microservices application.”

Requirements

Conditions that dictate the output’s format and constraints.

“The outline should be a numbered list with a maximum of five top-level items.”

Instructions

Guidance on how to execute the task. Provides intermediate steps or examples.

“For each microservice, provide a brief description and a list of its core dependencies.”

Types of Prompt Engineering

Fundamental prompting

Zero-Shot Prompting

  • The most basic prompt
  • Only on pre-trained knowledge
  • Follows the instruction in the prompt
  • The baseline for anything else
  • Issues with knowledge not in the model

Few-Shot Prompting

  • Add representative input and output examples to illustrate desired format, style and reasoning pattern
  • The examples (in the prompt) provides the model with in-context guidance
  • E.g. examples of Json provided
  • Makes prompts more reliable
  • Fitting with too many or too few examples…

Chain-of-Thought ( CoT ) Reasoning

A method that guides the model to break down a complex problem into a series of “intermediate reasoning steps” that logically lead to a final answer

This approach simulates a human-like problem-solving process and is particularly effective for tasks involving arithmetic, commonsense, and symbolic reasoning

“Zero-Shot CoT” - “Let’s think this through step by step”

  • Can unlock sophisticated problem-solving capacity within the model

The capacity to “think out loud” provides an interpretable window into the model’s behavior, allowing developers to debug where a reasoning path may have gone wrong.

  • e.g. a math problem where the model shows its work
  • Provides a more  transparrent and trustworthy final output

Tree-of-Thought ( ToT ) Exploration

ToT explores multiple reasoning paths in parallel, structuring the problem-solving process like a decision tree

This approach allows the model to brainstorm different potential solutions, evaluate each one, and even backtrack if a particular path proves to be unproductive

Retrieval-Augmented Generation (RAG)

RAGs  addresses a core limitation of LLMs: their reliance on static training data, which can be outdated or lack domain-specific information

RAG mitigates this by grounding the model’s responses in external, up-to-date knowledge

Security

Prompt Injection - this attack occurs when an attacker crafts a deceptive prompt to manipulate the LLM’s outputs, overriding its original programming

  • Injection aims to override instructions
  • Direct – in the prompt
  • Indirect – instruct the LLM to read webpages or similar with hidden commands

Jailbreaking – an attack aimed at convincing the model to disregard its built-in safety guardrails and respond to requests it has been programmed to refuse

  • jailbreaking aims to bypass ethical or safety controls
