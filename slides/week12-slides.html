MCP - Model Context Protocol

  • MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems. (https://modelcontextprotocol.io/docs/getting-started/intro)
  • Proposed by Anthropic in November 2024
    • Using MCP, AI applications like Claude or ChatGPT can connect to data sources (e.g. local files, databases), tools (e.g. search engines, calculators) and workflows (e.g. specialized prompts)—enabling them to access key information and perform tasks.

What can MCP enable? (examples)

  • Agents can access your Google Calendar and Notion, acting as a more personalized AI assistant.
  • Claude Code can generate an entire web app using a Figma design.
  • Enterprise chatbots can connect to multiple databases across an organization, empowering users to analyze data using chat.
  • AI models can create 3D designs on Blender and print them out using a 3D printer.

Why does MCP matter?

  • Developers: MCP reduces development time and complexity when building, or integrating with, an AI application or agent.
  • AI applications or agents: MCP provides access to an ecosystem of data sources, tools and apps which will enhance capabilities and improve the end-user experience.
  • End-users: MCP results in more capable AI applications or agents which can access your data and take actions on your behalf when necessary.

MCP example - Context7

  • “Context7” is the name of a specific software platform and Model Context Protocol (MCP) server designed to provide up-to-date, version-specific documentation and code examples to AI coding assistants and Large Language Models (LLMs)
  • Key aspects of Context7 include:
    • Accurate Information: It extracts high-quality, relevant code snippets from official documentation sources (like Markdown, plain text, or Jupyter notebooks), ensuring the AI works with the latest APIs and best practices.
    • Integration: It works with various AI clients and IDEs that support the Model Context Protocol (MCP).
    • Ease of Use: Developers can often trigger it within their prompts by simply adding the phrase “use context7” to a query in a compatible editor.
    • Problem Solver: It addresses the challenge of AI models having knowledge cutoffs, which makes them unaware of recent library updates, new features, or breaking changes.

MCP and AI Agents

  • MCPs are the agent’s tools

MCP vs. API

  • APIs are the old way (or used to be) — powerful, but not built for AI.

  • MCP is the new standard — dynamic, self-describing, and AI-native.

  • API – software to software

  • MCP – for LLMs to fetch context and tools

  • While APIs are an interface meant to utilized by developers, MCP is an interface/wrapper around APIs meant to be utilized by LLMs.

  • Or at least API was the old (last year) - we are starting to use APIs again over MCP - why?

MCP vs. API

  • Discovery – ask the MCP for its tools
  • Unlike traditional APIs, where every integration is custom, MCP standardizes the interface.
  • An AI agent can interact with any MCP-compatible service without needing prior knowledge of its specifics.
  • API creates breaking changes. MCP can be used immediately.

Two Core Problems MCP Solves

  • LLMs need two things from external systems:
    • Context — Structured data (documents, database records, knowledge bases).
    • Tools — Actions they can perform (search the web, send an email, run code).

Dynamic discovery

  • AI agents can ask a server what it can do at runtime
    • An MCP client sends a request like tools/list to discover available functions.
    • The server responds with descriptions, input/output formats, and usage examples.
    • The AI can then invoke those tools without pre-programmed integration.

CLI vs. MCP — The Trade-off

  • MCP is great for discovery and standardization
  • But MCP servers are token-heavy — schema definitions eat context fast
  • Example:
    • A single GitHub MCP integration uses ~55,000 tokens just for tool definitions
    • CLI tools use ~4,150 tokens for the same task — a 35x reduction
  • More tokens used on tools = less room for actual reasoning

CLI vs. MCP — When to use what

MCP CLI
Token cost High (~55K for GitHub) Low (~4K)
Model familiarity Must learn schemas at runtime Pre-trained on billions of CLI examples
Composability Limited Natural (piping, chaining)
Best for Discovery, permissions, non-CLI APIs Reasoning-heavy agent tasks
  • CLI wins on efficiency. MCP wins on structure and access control.

MCP in docker

  • Many MCP servers ship as Docker images — no local install needed
  • Sandboxed and easy to share across a team
  • Run a server with a single command:
  • docker run -p 3000:3000 mcp/github

Use of MCP in AI — Where do clients live?

  • Desktop apps — Claude Desktop, Cursor, Windsurf
    • Configure via claude_desktop_config.json
  • CLI — Claude Code, codex
  • Hosted/cloud — n8n, Zapier, custom backends, etc.
    • MCP servers called from workflows

n8n MCP server

  • n8n exposes its workflow engine as MCP tools
  • An AI agent can create, trigger, and modify n8n workflows through chat
  • Example prompt: “Make a workflow that sends me a Slack message when a GitHub PR is opened” — n8n builds it
  • This is meta-automation: AI building automation on your behalf
  • Requires no manual drag-and-drop in the n8n UI

Install n8n MCP and skills

  • n8n mcp https://github.com/czlonkowski/n8n-mcp
    • Provides AI assistants with comprehensive access to n8n node documentation, properties, and operations
    • Knowledge about 1396 n8n nodes
    • No more reliance on what the LLM is trained on - or guesses
  • Claude skill set for n8n https://github.com/czlonkowski/n8n-skills
    • teaches AI assistants how to build production-ready n8n workflows using the n8n-mcp MCP server.
