Why this project?

  • You have learned the core building blocks:
    n8n · agents · RAG · MCP · prompt engineering
  • Now it is time to put them together in a real system
  • The goal is a working agent system that solves an actual problem
  • Not a sandbox — a bounded system you can demonstrate

What you have to build

  • An AI agent system for a case of your own choice
  • The system must include:
    • Vector RAG — retrieve relevant content from your corpus
    • Graph RAG — represent relationships between concepts, sources, tasks or requirements
    • n8n — at least one workflow
    • MCP — expose a workflow or RAG as a tool the agent can call
  • The agent must be usable through a real interface (Telegram, Discord, email, …)
  • You must write a 5-page report and demonstrate the system at the oral exam

Choose your own case

The case must be relevant and bounded — something a real user would want

  • Thesis / academic project support
  • Software development assistant
  • Research literature manager
  • Customer support agent
  • Project management assistant
  • Content production assistant
  • Game companion — lore, quests, factions
  • Personal trainer — workouts, goals, recovery
  • … or something else you justify

The exact functions depend on your case. The important thing is that the system solves a real problem.

What makes a good case?

  • Good case:
    • Has a clear user and a real problem
    • Has a natural corpus for RAG (documents, guides, notes, data)
    • Has meaningful relationships for graph RAG (e.g. requirements → tasks → sources)
    • Benefits from automation through n8n workflows
  • Weak case:
    • “An agent that can answer any question”
    • No real corpus — just calls an LLM
    • MCP, n8n or RAG feel bolted on rather than useful

Personal AI assistants

A personal assistant is an AI agent that knows you — not just your questions.

General AI agent

  • Solves tasks for anyone
  • No memory of you
  • Starts over every time

Personal assistant

  • Knows your preferences and habits
  • Remembers previous conversations and tasks
  • Gets better the more you use it

What can a personal assistant do?

Information

  • Daily digest — news, your field
  • Research on topics you follow
  • Summarise emails and documents

Action

  • Bookings and calendar
  • Reminders and follow-up
  • Drafts for emails and messages

Available where you are — Telegram, WhatsApp, Discord — not just in a browser.

The agent is the intermediary between you and all your systems — you communicate in natural language, the agent handles the complexity.

Skills and prompts

  • Agents use skills — markdown documents that tell the agent how to behave
  • A skill is similar to an SOP or a prompt — it describes a task step by step
  • You must create at least one prompt or skill yourself
  • This can be a custom skill in NanoClaw or Hermes, or a prompt in an n8n agent node
  • Include it in your report with an explanation of your design choices

NanoClaw

  • Lightweight, open-source AI agent framework (~3,900 lines — small, readable)
  • Runs each agent session in an isolated Docker container
  • Connects to WhatsApp, Telegram, Slack, Discord, Gmail and more
  • Runs on your own machine — no cloud, no data sharing

“Give the AI agent hands — but put it in a cage.”

NanoClaw: how it works

You send a message (Telegram / WhatsApp)
        ↓
NanoClaw receives the message
        ↓
Spawns an isolated Docker container
        ↓
LLM reasons and uses tools
        ↓
Reply sent back to you
  • Each user gets their own container, filesystem and memory
  • The agent cannot “escape” and affect other sessions

Hermes Agent

  • Open-source AI agent by Nous Research (MIT licence)
  • 95,000+ GitHub stars in 7 weeks — fastest-growing agent framework in 2026
  • Runs locally, on a VPS or serverless
  • Model-agnostic — Claude, GPT, Llama, Mistral, local Ollama, any OpenAI-compatible endpoint

“The agent that grows with you.”

Hermes: self-improvement and memory

Self-improvement

  • Creates skills from its own experience
  • Finds and reuses previous solutions instead of starting over
  • Benchmarks show 40% faster on research tasks vs. a fresh agent

3-layer memory

Layer What is stored
Short-term Active conversation and context
Long-term Facts, preferences, previous tasks
Skills library Reusable skills created by the agent

Memory survives restarts — the agent remembers you next time.

Platform options: NanoClaw vs Hermes

NanoClaw Hermes Agent
Focus Isolated tool execution Self-improvement via skills
Container isolation Yes — Docker per session No
Local LLM support Limited Yes — model-agnostic
Self-improvement No Yes — skills library
Setup Moderate Moderate
Best for Safe tool use, automation Flexible, skill-driven agents

Both connect to Telegram / WhatsApp / Slack.
Choose based on your case.

Suggested architecture

User (Telegram / Discord / …)
        │
        ▼
  Agent platform
  (NanoClaw or Hermes)
        │
   ┌────┴────┐
   │         │
  LLM    MCP server
           │
    ┌──────┼──────┐
    │      │      │
  n8n   Vector  Graph
 workflow  RAG    RAG
  • The agent uses the LLM to reason and the MCP server to act
  • MCP exposes your n8n workflows and RAG pipelines as callable tools

Component roles

Component What it does in the system
Agent platform Receives messages, reasons, calls tools
LLM Generates responses and decisions
MCP server The bridge — exposes tools to the agent
n8n workflow Automates actions (send email, fetch data, …)
Vector RAG Finds relevant chunks from your corpus
Graph RAG Traverses relationships (sources → concepts → tasks)
Interface How the user talks to the system
